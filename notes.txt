[NOTES]

- the kernel reservation is only safe today because link.ld aligns _kernel_start and
  _kernel_end to 4096. without that ALIGN the kernel's last page stays marked free and
  the allocator can hand out kernel memory. this is the same latent rounding exposure
  as the first entry, not a separate mechanism: the aligned edges are exactly what
  makes both current reservations reserve the right page count

- kprintf %d negates INT32_MIN, which is undefined, ubsan flags it. prints the right
  digits only by accident at -O2

- HEAP: HeapGrow now asks the page allocator for a run that starts at the highest
  recorded segment end, which acts as a growth hint rather than a hard adjacency
  requirement. block and segment boundary checks use the owning segment for each
  block, so the heap no longer depends on one global tail pointer for correctness.
